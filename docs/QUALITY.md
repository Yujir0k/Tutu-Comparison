# Контроль качества

## Автоматический quality gate

`pnpm quality` является обязательной проверкой перед релизом:

1. ESLint проверяет TypeScript, React Hooks, неиспользуемый код, `any` и случайный `console.log`.
2. TypeScript работает в strict mode с `noUnusedLocals` и `noUnusedParameters`.
3. Node test runner проверяет scoring, валидацию, кэш и HTTP-контракт.
4. Vite и `tsc -p tsconfig.server.json` создают обе production-сборки.
5. Prettier подтверждает единый формат.

CI повторяет тот же gate на чистой установке зависимостей.

## Покрываемые риски

| Риск                                               | Проверка или защита   |
| -------------------------------------------------- | --------------------- |
| Дешёвый, но рискованный маршрут ошибочно побеждает | scoring test          |
| Малое число отзывов даёт ложную уверенность        | scoring test          |
| Отсутствующее поле превращается в выгоду           | scoring test          |
| Фильтр содержит неподдерживаемое значение          | validation test       |
| Подменён город или product checkout                | validation test       |
| Кэш бесконечно растёт или повреждён                | cache test            |
| API возвращает HTML/stack trace вместо JSON        | integration test      |
| Защитные заголовки отсутствуют                     | integration test      |
| Большая выдача делает правила медленными           | performance assertion |

## Ручной smoke test

- desktop: поиск всех видов транспорта, добавление и удаление сравнения;
- hotel: фильтры без кнопки подтверждения, shortlist больше четырёх, стрелки таблицы;
- mobile 390 px: поиск, фильтры, карточки, dock сравнения;
- внешний переход: ссылка открывает оригинальный Туту;
- отказ MCP: нет выдуманных карточек, отображается честная ошибка или помеченный кэш.

## Definition of done

- рабочая директория не содержит dead code, mock data и второй lockfile;
- lint, typecheck, tests, build и format check проходят без предупреждений;
- документация соответствует текущим командам и архитектуре;
- пользовательский сценарий проверен в production-сборке, а не только в dev mode.
